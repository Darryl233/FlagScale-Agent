# 平台适配与性能指标解释

训练优化方法通常具有跨平台的数学或调度依据，但可用参数、执行后端和收益取决于具体实现。FlagScale、Megatron-LM-FL、TransformerEngine-FL 与 torch_npu/CANN 分别参与配置生成、训练调度、算子分派和设备执行，单个层次的能力不能代表整条路径的能力。

## 方法与实现的区别

| 优化方向 | 可复用的原理 | 平台相关的条件 |
| --- | --- | --- |
| 并行与分片 | 用通信换取单设备状态或计算量的降低 | 进程组构造、分片形状、拓扑、collective 与 checkpoint schema |
| 激活重计算 | 减少保存的中间量，增加反向阶段的重放计算 | checkpoint 边界、RNG、融合算子的内部重物化和通信重放 |
| 通信重叠 | 在依赖允许时并发计算与通信，减少暴露等待 | stream/event 依赖、buffer 生命周期、通信与计算资源竞争 |
| 执行图 | 复用执行计划，减少重复的 host 调度与下发 | 可捕获算子、动态 shape、RNG、collective 和 replay 支持 |
| 算子融合 | 减少中间张量搬运、分配与小任务下发 | 数值语义、布局、临时资源、编译器支持与后端注册 |
| 状态卸载 | 用主机或存储容量换取设备显存 | 传输带宽、预取时序、可隐藏时间与主机内存压力 |

CUDA 的 NCCL、Userbuffers、SM margin、allocator 或 CUDA Graph 参数不能按名称映射成 HCCL/NPU 参数。相似接口也可能在默认值、同步语义、支持精度和回退行为上不同。实际能力由配置是否被消费、公共接口是否绑定到目标实现，以及完整前后向是否保持语义共同决定。

## 性能表字段与测量对象

文件名不能确定数据粒度。同名 `op_summary.csv` 在不同导出版本中可能包含逐任务记录或不同层次的汇总；列名、单位与 producer 版本才决定可计算的指标。

- 带 `Task Start Time(us)` 和 `Task Duration(us)` 的逐任务记录可形成执行区间。
- 只有次数和累计时长的汇总表可用于热点排序，不能还原任务先后、重叠或空隙。
- `Task Wait Time(us)` 有独立的字段定义，不能直接当作 host 下发延迟或设备全局空闲时间。
- host、设备及不同 rank 的时钟域可能不同。未经校准的绝对时间戳不能直接相减。

字段语义参考 [CANN profiling 算子表说明](https://www.hiascend.com/document/detail/zh/canncommercial/81RC1/devaids/devtools/profiling/atlasprofiling_16_0067.html)；具体分析仍取决于实际导出版本与表头。

## 累计耗时、覆盖率与关键路径

计算和通信任务可能跨 stream 重叠，因此累计耗时之和不等于 step 耗时。窗口内任务区间的并集表示已观测任务的时间覆盖；并集中的计算/通信交集表示时间上的重叠，不能仅由累计时长推导。

采样窗口中的未覆盖部分也可能来自采集截断、未记录的任务类型或关联缺失。它本身不足以证明物理设备空闲。通信暴露时间还取决于计算的生产/消费依赖；有时间重叠不代表通信等待已经完全隐藏。

AICPU 任务不一定是错误回退，例如某些通信机制可能包含预期的 AICPU 工作。归因需要结合任务职责、预期后端和关键路径代价，而不是仅看任务类型。

利用率、等待比例或毫秒级间隔可作为筛选指标，但不存在适用于所有芯片、模型和版本的统一诊断阈值。缺少 PMU 或对应硬件计数时，时间覆盖率不能证明算力饱和。

## 配置变化与训练语义

并行度的算术约束只是配置合法性的一部分。dense 与 expert 进程组、参数分片、调度约束及目标后端能力仍需分别成立；简单 world-size 公式不能覆盖所有 CP/EP/ETP 组合。

强制均衡路由、丢弃 token、更改 batch/序列长度或降低精度会改变可比性。它们可以帮助区分负载不均、容量和计算量等因素，但其性能结果不能直接表示原任务在相同训练语义下的优化收益。

优化开关也可能同时触发多个派生变化，例如重计算重放通信、overlap 增加 buffer，或融合引入额外布局转换。单项收益不可直接相加，组合效果取决于新的资源峰值和关键路径。

## 结论的适用范围

源码阅读可解释接口与约束；可导入或构造成功只说明对应初始化路径可用；完整更新的数值检查与稳定性能比较回答不同问题。版本、模型结构、实际 shape、精度、布局和数据分布共同限定结论的范围。

算子微基准、公共 API 完整调用和端到端训练包含的成本不同。kernel 变快而公共调用变慢，可能由转换、分配或同步抵销收益；公共调用变快也不必然改善训练关键路径。
