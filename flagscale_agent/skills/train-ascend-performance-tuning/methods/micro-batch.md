# 保持 GBS 的 micro-batch 调整

## 适用条件

实际运行需要可运行基线；仅生成/分析候选时可从配置开始，注明基线未实测和缺少的框架检查。
取得配置中的 MBS、GBS、DP 和 pipeline 调度，区分请求值与已核实的生效值；本方法保留现有并行布局及训练语义。
DP/梯度累积关系不清楚时按 Knowledge 的 `ascend_training/search-space.md` 核对；
动态 batch 或自定义调度先确认可比较的固定阶段，不能直接套算式。

## 生成候选

1. 从父配置复制配方，确认字段位置（常见为 `train.model.micro_batch_size`），沿当前配置转换入口核对最终 argv，条件不足时标待验证。
2. 显存有余量且关注吞吐时优先测试一个更大 MBS；关注容量时测试更小 MBS。
   从当前值的相邻倍数/约数选取少量候选，只保留能整除 `GBS / DP` 且满足调度约束的值。
3. 只更改 MBS 及框架确实需要的梯度累积派生值，保留 GBS、数据顺序、模型、精度和优化器。
   返回父配置、假设（如减少每次更新的 microbatch 数）、完整差异及下述检查。

**静态例子**：GBS=64、DP=16、MBS=1 时，每次更新有 4 个 microbatch。
候选 MBS=2 对应 2 个，MBS=4 对应 1 个；MBS=3 不整除而拒绝，MBS=8 也不合法。
这只是候选生成示例，是否可运行和加速由主循环实测决定。

## 额外检查

- **启动前**：核对实际 `GBS = MBS × DP × 累积次数`、pipeline 调度要求和完整有效配置差异。
- **短跑**：核对每次更新实际消费的样本数不变、没有丢样本/跳步，MBS 和累积次数实际生效。
- **采纳前**：从相同模型/优化器状态和相同样本序列比较数次更新，按事先约定的容差检查
  loss/梯度及参数更新；仅 loss 有限不证明批量变更等价。比较细则按需查 `ascend_training/measurement-and-records.md`。

## 结果反馈

主循环返回结果后：有收益且有余量则考虑下一个合法相邻值；OOM 则拒绝该候选，回到较小可行值。
更大 MBS 没收益不等于方法失效，保留更快的有效配置并结束该方向或测试尚未覆盖的邻居。
质量失败则拒绝当前候选，先核对样本/累积语义；全部候选无效或无收益时返回原配置与原因。
不要因为本方法没有提升就自动扩大到整套并行、算子或图模式搜索。
